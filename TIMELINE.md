## 2026-11-04 — Схема запуска: код на PC-108-7, Fusion на Windows

- Код, venv и MCP-сервер живут на PC-108-7 (работает постоянно). Fusion с add-in — на Windows рабочей машины (dual-boot), там же Claude Code.
- Claude Code на Windows запускает сервер stdio-командой через ssh с обратным туннелем: `ssh -R 9876:localhost:9876 PC-108-7 "... fusion360-mcp-server"`.
- Почему туннель, а не `FUSION_MCP_HOST=0.0.0.0`: Windows за домашним NAT, PC-108-7 доступен только через VPN и не может подключиться к ней сам; add-in остаётся на localhost и не выставляет `execute_code` в сеть.
- Почему не постоянный HTTP-сервер: сервер умеет только stdio, а stdio через ssh даёт то же самое без изменений кода; при закрытии Claude закрывается и туннель.
- Ограничение: одна сессия за раз (порт 9876 на PC-108-7 один; `ExitOnForwardFailure` делает конфликт явным).
- Проверено с Linux-машины: initialize и tools/call проходят через ssh, вызов доходит по туннелю обратно.

## 2026-11-04 — Транзакции: каждый вызов, меняющий модель, внутри Fusion Command

- Проблема (fusion-agent-notes, «неудачный вызов тихо меняет фичу», «undo вслепую»): вне команды каждый вызов API — отдельная запись undo, упавший инструмент оставляет частичные изменения, `undo` откатывает один вызов API, а не инструмент.
- Решение: `addon/server/transaction.py`. Мост запускает временную команду `Fusion360MCP_Transaction`, работа идёт в её execute; при `ok: false` ставим `executeFailed = True` и помечаем ответ `rolled_back: true`. Имя шага undo — `MCP: <инструмент>`.
- Основание: документация Fusion — правки в execute-обработчике собираются в одну транзакцию с именем команды; `CommandEventArgs.executeFailed` прерывает транзакцию. Менеджера транзакций в API нет (Brian Ekins, форум Autodesk), так что это единственный штатный путь.
- `CommandDefinition.execute()` отложенный (форум, не документация) → мост ставит очередь на паузу, пока команда не завершится (destroy). Команда, не стартовавшая за 5 с, освобождается с `TRANSACTION_FAILED`.
- Вне транзакции: чтение, `undo`, `reload_handler`, `set_design_type`, экспорт, CAM — они сами управляют UI или ждут Fusion (`doEvents`, смена workspace). Список сверяется тестом с `_READ_ONLY` из tools.py.
- Флаг: `FUSION_MCP_TRANSACTIONS=0` возвращает прежнее поведение.
- Проверено: логика моста на поддельном `adsk` (tests/test_transaction.py). Не проверено на живом Fusion:
  1. команда без полей ввода выполняется сразу, без диалога;
  2. `executeFailed` действительно откатывает изменения (и не показывает модальное окно, которое заблокирует главный поток);
  3. смена `cmd_def.name` перед запуском меняет имя шага в истории undo;
  4. `execute_code` и фичи (extrude, fillet, правка эскиза) работают внутри команды; `undo` отменяет весь вызов инструмента;
  5. что происходит с активной командой пользователя в UI в момент вызова.

## 2026-11-04 — Именованные точки отката через журнал undo

- Инструменты `create_checkpoint`, `list_checkpoints`, `rollback_to_checkpoint` (`addon/server/history.py`). Выбран вариант «через историю undo»: шаг MCP = одна транзакция = один undo, откат = N undo.
- Прочитать список undo через API нельзя (форум Autodesk: «transactions … are not currently supported by the API so its not possible to find out whats in the undo list»). Поэтому журнал — зеркало: шаги MCP пишет мост после успешной транзакции, остальные завершённые команды (UI, скрипты) ловим через `UserInterface.commandTerminated` (документирован, `CompletedTerminationReason`) и пишем как foreign. Undo (`UndoCommand`) снимает последнюю запись; redo пишется как foreign.
- Откат отказывает (`HISTORY_CONFLICT`), если после точки есть foreign-записи или число элементов таймлайна не совпадает с записанным после последнего шага (вторая проверка ловит то, что журнал не увидел). `force=true` откатывает всё равно.
- Журнал и команды живут в мосте (`BRIDGE_COMMANDS`), а не в `CommandHandler`, чтобы переживать `reload_handler`. Без транзакций команды отвечают ошибкой.
- Документ отождествляется по имени — грубо, проверить на живом Fusion.
- Проверено на поддельном `adsk` (tests/test_bridge.py). Не проверено на живом Fusion:
  1. приходит ли `commandTerminated` для `UndoCommand` (и Ctrl+Z), и с каким id;
  2. какие завершённые команды не создают шаг undo (выбор, камера, измерения) — их добавить в `IGNORED_COMMAND_IDS`; все foreign id пишутся в лог;
  3. выполняется ли `UndoCommand.execute()` + `doEvents()` синхронно внутри обработчика (смотреть `timeline_matches_checkpoint`).

## 2026-11-04 — Таймлайн и граф зависимостей (только чтение)

- Инструменты `get_timeline`, `get_feature_info`, `get_dependents`; логика в `addon/server/model_graph.py` (без импорта `adsk`, тестируется на фейках).
- Готового графа зависимостей в API нет (форум Autodesk; `CustomFeatureDependencies` есть только у пользовательских фич). Граф строится из входов: обходим известный список свойств-входов (взят из официальных заглушек `adsk` 2.0.12157 с PyPI, ~2022 — новых свойств там может не быть), каждый объект сводим к узлу: профиль/кривая → эскиз, тело → тело, грань/ребро → тело + фича, создавшая её грани (`Feature.faces` по `entityToken`). У эскизов входы — `referencePlane` и спроецированная геометрия (`isReference`/`referencedEntity`): скрытые ссылки из заметок.
- Почему список свойств, а не разбор по типам: ~40 типов фич, одинаковые имена свойств; новый тип с теми же именами работает без кода.
- Связи «через тело» по умолчанию выключены (`include_bodies`): в однотельной модели (WING_1, 300 фич) они связывают всё со всем.
- Входы читаются при текущем положении маркера, грани/рёбра — из текущего состояния модели: результат — оценка «что может сломаться», не доказательство.
- Свойства, чтение которых падает (сломанная фича), попадают в `unreadable`, а не роняют вызов. `healthState` падает для части типов (подтверждённый баг Fusion) → `health: unknown`.
- `get_feature_info` отдаёт модельные параметры фичи (`ModelParameter.createdBy`) с выражениями и `dependentParameters` — нынешний `get_parameters` показывает только пользовательские.
- Не проверено на живом Fusion:
  1. все имена свойств на текущей сборке; включает ли `timeline.item()` группы и элементы внутри них;
  2. сопоставление граней по `entityToken` между `Feature.faces` и входами;
  3. время `get_dependents`/`get_feature_info` на большой модели (оба обходят весь таймлайн; при 30 с таймауте может понадобиться кэш).

## 2026-11-05 — Оставшиеся пункты fusion-agent-notes (разделы 3–4)

- **Таймаут на пересчёте → фоновые задачи.** `start_job(tool, params)` ставит команду в очередь и сразу возвращает id; `get_job` читает состояние в сокет-потоке, не дожидаясь главного потока Fusion. Пересчёт в Fusion синхронный, асинхронным его сделать нельзя — можно только не держать на нём вызов MCP. Сам Fusion на время пересчёта по-прежнему занят.
- **Пересчёт до маркера.** `set_timeline_marker` (позиция / до / после элемента / конец) и `compute_all` (`Design.computeAll`). Перемещения маркера идут вне транзакции и пишутся в журнал как `untracked`: попадают ли они в undo, неизвестно, поэтому откат через них блокируется (`force=true` — в обход). Рекомендуемый порядок: сначала маркер, потом `create_checkpoint`.
- **Пробный прогон → не копия документа, а транзакция, которая всегда откатывается.** `dry_run(tool, params)`: снимок проблем таймлайна до и после правки, `executeFailed = True`, в журнал не пишется. Копия документа в Fusion требует сохранения в облако; откат той же транзакцией дешевле и не плодит файлы. Опирается на то же непроверенное поведение `executeFailed`, что и транзакции.
- **API не даёт править фичу → `recreate_feature`.** `OffsetFacesFeature` (новые грани по точкам, `Component.findBRepUsingPoint`; дистанция — выражение модельного параметра) и `SweepFeature` (новый профиль; путь, операция, ориентация, distanceOne/Two, taper, twist копируются; guide rail пока нет). Порядок: прочитать настройки → `rollTo(before)` → создать новую → удалить старую → вернуть имя и маркер. Всё в одной транзакции. `OffsetFacesFeatures.createInput(faces, distance)` появился в ноябре 2025 (документация Autodesk); upstream `offset_faces` создаёт другое — `OffsetFeature` (смещённую поверхность).
- **Потерянные ссылки → `snapshot_references` / `check_references`.** Снимок хранит для каждой фичи её входы-грани и рёбра с координатой (центроид грани, центр bbox ребра) и размером (площадь/длина). После правки: какие пропали (совпадение по телу и координате в пределах 1e-3 см) и до 3 кандидатов того же тела — ближайших по координате, затем по размеру. Снимок живёт в `CommandHandler` и теряется при `reload_handler`.
- **Системный промпт → инструкции сервера.** `guide.py`: правила раздела 4 отдаются клиенту в `instructions` при подключении и промптом `edit-existing-model`. Тест следит, чтобы в правилах упоминались только существующие инструменты.
- **Замысел вне модели → `set_design_note` / `get_design_notes`** в атрибутах дизайна (группа `fusion360mcp.intent`); запись — в транзакции.
- `reload_handler` выведен в инструменты.
- Не сделано: камера/`viewExtents` и размеры эскизов на рендере (раздел 2) — не трогал `render_view`; энкодер (раздел 5) — отдельная работа. AGENTS.md/README (авторские) не обновлял: там 93 инструмента, теперь 110.
- Не проверено на живом Fusion: пересоздание фич (особенно `rollTo` + `deleteMe` + переименование в одной команде), `findBRepUsingPoint` в откатанном состоянии, `computeAll` и движение маркера внутри/вне команды, сохраняются ли атрибуты при undo.

## 2026-11-05 — Камера, размеры эскизов, объём ответов (раздел 2 заметок)

- **Камера.** Докстринг API: `Camera.viewExtents` — радиус сферы вокруг цели, и его установка может сдвинуть eye/угол у перспективной камеры — отсюда «странное» поведение. `render_view(focus | center+radius)`: ортографическая камера, eye/target/up, `isFitView=False`, extents — последним; затем применённая камера читается обратно и возвращается (`camera.view_extents` vs `requested_extents`), исходная камера восстанавливается.
- **Размеры эскизов.** `focus=<эскиз>`: камера по нормали эскиза (x × y), на время снимка `isVisible` и `areDimensionsShown` включаются и затем возвращаются как были.
- **Огромные дампы.** `features_near(point, radius)` — элементы таймлайна у точки (расстояние до bbox созданных граней, у эскиза — до его bbox), чтобы разбирать один узел без выгрузки модели. `get_timeline` — фильтры `name_contains`, `types`. Upstream `get_scene_info` — `limit` (50) на списки тел и эскизов с флагом `truncated`; счётчики точные.
- Документ по ветке — `docs/EXPERIMENTAL.md` (свой; авторские README/AGENTS.md не меняли по правилам CLAUDE.md).
- Не проверено на живом Fusion: применяется ли extents так, как задан; совпадает ли `xDirection × yDirection` с направлением «смотреть на эскиз»; видны ли размеры на `saveAsImageFile`.
