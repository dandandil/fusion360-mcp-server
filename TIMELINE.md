# TIMELINE

Технические решения и их обоснование. Это результаты наших опытов, а не ground truth: перепроверять при необходимости.

## 2026-11-04 — Окружение

- Зависимости ставим через pip в `.venv` репозитория (Python 3.12): uv на PC-108-7 не установлен. Версии свежие, не из `uv.lock` (mcp 1.30.0, anyio 4.16.0, click 8.5.0). Проверка: 367 тестов, ruff чисто, mock-режим отвечает по MCP.

## 2026-11-04 — Схема запуска: код на PC-108-7, Fusion на Windows

- Код, venv и MCP-сервер живут на PC-108-7 (работает постоянно). Fusion с add-in — на Windows рабочей машины (dual-boot), там же Claude Code.
- Claude Code на Windows запускает сервер stdio-командой через ssh с обратным туннелем: `ssh -R 9876:localhost:9876 PC-108-7 "... fusion360-mcp-server"`.
- Почему туннель, а не `FUSION_MCP_HOST=0.0.0.0`: Windows за домашним NAT, PC-108-7 доступен только через VPN и не может подключиться к ней сам; add-in остаётся на localhost и не выставляет `execute_code` в сеть.
- Почему не постоянный HTTP-сервер: сервер умеет только stdio, а stdio через ssh даёт то же самое без изменений кода; при закрытии Claude закрывается и туннель.
- Ограничение: одна сессия за раз (порт 9876 на PC-108-7 один; `ExitOnForwardFailure` делает конфликт явным).
- Проверено с Linux-машины: initialize и tools/call проходят через ssh, вызов доходит по туннелю обратно.

## 2026-11-04 — Транзакции: каждый вызов, меняющий модель, внутри Fusion Command

- Проблема (fusion-agent-notes, «неудачный вызов тихо меняет фичу», «undo вслепую»): вне команды каждый вызов API — отдельная запись undo, упавший инструмент оставляет частичные изменения, `undo` откатывает один вызов API, а не инструмент.
- Решение: `addon/server/transaction.py`. Мост запускает временную команду `Fusion360MCP_Transaction`, работа идёт в её execute; при `ok: false` ставим `executeFailed = True` и помечаем ответ `rolled_back: true`. Имя шага undo — `MCP: <инструмент>`.
- Основание: документация Fusion — правки в execute-обработчике собираются в одну транзакцию с именем команды; `CommandEventArgs.executeFailed` прерывает транзакцию. Менеджера транзакций в API нет (Brian Ekins, форум Autodesk), так что это единственный штатный путь.
- `CommandDefinition.execute()` отложенный (форум, не документация) → мост ставит очередь на паузу, пока команда не завершится (destroy). Команда, не стартовавшая за 5 с, освобождается с `TRANSACTION_FAILED`.
- Вне транзакции: чтение, `undo`, `reload_handler`, `set_design_type`, экспорт, CAM — они сами управляют UI или ждут Fusion (`doEvents`, смена workspace). Список сверяется тестом с `_READ_ONLY` из tools.py.
- Флаг: `FUSION_MCP_TRANSACTIONS=0` возвращает прежнее поведение.
- Проверено: логика моста на поддельном `adsk` (tests/test_transaction.py). Не проверено на живом Fusion:
  1. команда без полей ввода выполняется сразу, без диалога;
  2. `executeFailed` действительно откатывает изменения (и не показывает модальное окно, которое заблокирует главный поток);
  3. смена `cmd_def.name` перед запуском меняет имя шага в истории undo;
  4. `execute_code` и фичи (extrude, fillet, правка эскиза) работают внутри команды; `undo` отменяет весь вызов инструмента;
  5. что происходит с активной командой пользователя в UI в момент вызова.

## 2026-11-04 — Именованные точки отката через журнал undo

- Инструменты `create_checkpoint`, `list_checkpoints`, `rollback_to_checkpoint` (`addon/server/history.py`). Выбран вариант «через историю undo»: шаг MCP = одна транзакция = один undo, откат = N undo.
- Прочитать список undo через API нельзя (форум Autodesk: «transactions … are not currently supported by the API so its not possible to find out whats in the undo list»). Поэтому журнал — зеркало: шаги MCP пишет мост после успешной транзакции, остальные завершённые команды (UI, скрипты) ловим через `UserInterface.commandTerminated` (документирован, `CompletedTerminationReason`) и пишем как foreign. Undo (`UndoCommand`) снимает последнюю запись; redo пишется как foreign.
- Откат отказывает (`HISTORY_CONFLICT`), если после точки есть foreign-записи или число элементов таймлайна не совпадает с записанным после последнего шага (вторая проверка ловит то, что журнал не увидел). `force=true` откатывает всё равно.
- Журнал и команды живут в мосте (`BRIDGE_COMMANDS`), а не в `CommandHandler`, чтобы переживать `reload_handler`. Без транзакций команды отвечают ошибкой.
- Документ отождествляется по имени — грубо, проверить на живом Fusion.
- Проверено на поддельном `adsk` (tests/test_bridge.py). Не проверено на живом Fusion:
  1. приходит ли `commandTerminated` для `UndoCommand` (и Ctrl+Z), и с каким id;
  2. какие завершённые команды не создают шаг undo (выбор, камера, измерения) — их добавить в `IGNORED_COMMAND_IDS`; все foreign id пишутся в лог;
  3. выполняется ли `UndoCommand.execute()` + `doEvents()` синхронно внутри обработчика (смотреть `timeline_matches_checkpoint`).
